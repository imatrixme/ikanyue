## Context

课程点领域服务、PocketBase 集合、事务 Batch、幂等、课堂冻结/结算、教师工作量和对账已经在 `ikanyue.mapi.hono` 中实现并通过本地测试。当前交付缺口集中在三个层面：学生 API 仍暴露账本模型，小程序把课程点原型作为“我的”二级入口，Admin 仍使用 `AppView` 内存状态承载三个积分轻量页面且缺少课程管理命令。

本期面向学员、教务、财务、教师和管理员。小程序必须使用自然课程语言；Admin 可以查看账务细节，但主要工作流仍以课程、课包、报课、班级、课堂和核销组织。PocketBase 继续只负责存储，所有业务逻辑位于 Hono。

## Goals / Non-Goals

**Goals:**
- 小程序形成“活动、课程、积分、我的”四 Tab，课程 Tab 提供只读课程、课时、日程和记录。
- Admin 一次报课自动完成订单、课时发放、可选入班、审计和未来课堂同步任务。
- Admin 支持课程目录、课包价格、班级、课堂、人工出勤、核销、教师工作量、异常与审计工作区。
- 已发布课堂的名单变更保持显式、可预览、可审计。
- Hono、Admin、小程序四项覆盖率均达到 95%。

**Non-Goals:**
- 小程序自助报课、在线支付、学员自主预约或转课。
- 二维码签到、现场签到设备或签到与核销自动联动。
- PocketBase hooks、Docker 持续验证或生产发布。
- 将实物积分与课程课时合并为同一账本。

## Decisions

### 1. 学员课程投影与账本 API 分离

新增 `/v1/student/learning/*` 只读接口，返回 `courses`、`lessons`、`lessonRecords` 等学员模型。现有 `/v1/course-credits/*` 保留给内部迁移和兼容测试，但小程序不再调用其查询或命令。投影层组合课程类型、批次、课堂和事件，不返回 `creditTypeId`、`batchId`、`frozenQuantity`、`conversionRule`、`operationNo` 或原始事件 metadata。

选择 Hono 投影而不是仅在 Taro 映射，是为了让“不泄露课程点概念”成为服务端契约，避免错误消息、空状态或后续页面再次暴露账本字段。

### 2. 课程成为独立 Tab

Tab 顺序固定为“活动、课程、积分、我的”。课程首页展示下一节课、课程列表、有效期提醒和最近记录；课程详情、日程、课堂详情和课时记录使用普通页面。积分 Tab 保持实物积分语义，不与课时混用。

### 3. 自动报课使用主事务加 Outbox 同步

Admin 报课命令在一个 PocketBase SDK Batch 中写入订单/支付快照、课程课时批次、可选班级成员关系、操作记录、审计和 `ENROLLMENT_ACTIVATED` Outbox。未来课堂名单同步由幂等 worker 处理，避免一个报课事务因大量未来课堂超过 Batch 限制。

未发布课堂在发布时自然获取最新班级成员。已发布未来课堂只生成“待同步”预览，必须由有权限的操作者确认后才能修正名单并重新执行资格检查。

### 4. Admin 使用真实 URL 路由

用 `react-router-dom` 替换根级 `AppView` 切换。一级页面拥有稳定 URL；列表上下文保留在页面，详情使用 Drawer，高风险操作使用 Dialog，报课使用独立路由的分步表单。角色与 capability 同时控制导航可见性和服务端授权。

### 5. 手工出勤与核销分离

课堂名单初始出勤为 `pending`。授权教师或教务可批量标记“全部到课”并修正请假、迟到、缺席和取消；核销前必须调用预览接口，展示每名学员将扣除、退回或保持异常的课时及实际教师工作量。确认后复用现有原子 `settleSession`。已核销课堂只能通过 reversal 和重新结算更正。

### 6. Admin 目录命令使用显式资源服务

课程、课包、价格、班级和课堂不通过浏览器直连 PocketBase，也不使用通用集合 CRUD。Hono 为每类资源提供校验后的 create/update/publish 命令并写审计。列表和详情继续复用现有 Ops 查询投影。

### 7. 覆盖率按项目独立执行

- Hono 使用 Node test/c8，对本次新增路由、服务和投影执行 lines、branches、functions、statements 95% 门禁。
- Admin 使用 Vitest coverage，覆盖路由、API 客户端、状态、表单验证和工作流组件。
- Taro 使用 Vitest coverage，覆盖课程投影适配、页面状态、导航和文案边界。
- 编译产物契约额外检查课程 Tab、页面注册以及学员可见文本中不出现禁用术语。

## Risks / Trade-offs

- [报课成功后未来课堂异步同步存在短暂延迟] → Admin 展示同步状态，小程序只显示已完成投影，worker 幂等重试并进入异常中心。
- [已发布课堂名单自动变化破坏快照] → 仅生成预览，要求显式确认名单修正。
- [当前 Admin 类型和根状态文件继续膨胀] → 以领域目录拆分 API、类型、页面和测试，任何文件超过 500 行前拆分。
- [课程点内部错误消息泄露给学员] → 学员投影只返回稳定体验状态码，小程序禁止直接展示后端 message。
- [95% 分支覆盖可能被 UI 防御分支拖低] → 将业务决策下沉纯函数，组件测试覆盖可操作状态，第三方/启动胶水使用窄范围排除并记录理由。

## Migration Plan

1. 先发布 Hono 学员投影和 Admin 管理命令，不移除旧学生课程点接口。
2. 发布 Admin 路由化工作区和自动报课，使用本地数据完成报课、分班、课堂和核销闭环。
3. 发布小程序四 Tab 与只读课程页面，停止调用旧学生课程点命令。
4. 运行禁用术语与访问日志检查，确认旧命令无小程序流量后再标记 deprecated。
5. 最终发布前对生产备份演练迁移、回滚、Docker 构建和对账。

回滚时可独立回退 Admin 和小程序；Hono 新接口为新增接口，不改变现有账本数据。自动报课事务失败时由 Batch 全量回滚，异步同步失败保留 Outbox 和异常记录，不撤销已成功的报课主事实。

## Open Questions

- 请假、迟到、缺席和机构取消的最终扣课规则仍由版本化课堂规则决定，UI 不硬编码。
- 是否允许教师直接确认核销，或必须由教务二次确认，将通过 capability 配置而非分叉页面实现。
