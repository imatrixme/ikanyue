## Why

`kanyue.gateway` 的转发、策略、按环境上线与观测已经可以替代阿里云 API 网关，但“运行面”还不像一个成熟网关：

- 升级网关自身要停进程，重启期间端口没人监听，公网请求失败；
- 仓库没有 CI，网关、控制台、暴露清单的检查只在开发机上手动跑；
- 加密密钥（`--encryptionEnv`）泄露或到期后无法更换，库里、上线记录和最近可用快照里的密文只能用旧密钥解开；
- 只在开发机压测过，目标机器上的吞吐、长稳与真实 S3 恢复没有验证，阿里云在用能力也没有逐项对照；
- 管理面只有超管一种身份，必须人工 TOTP 登录，脚本与 CI 无法安全地自动上线；配置只能在控制台里点，不能评审和重建。

这些要在 `mapi.ikanyue.com` 切流（`add-kanyue-gateway` 5.4、5.5）之前或紧随其后补上。

## What Changes

按优先级分两段，P0 是切流前必须完成的，P1 紧随其后。

**P0 运行面**

- **零停机升级**：
  - 两个网关实例（主、备）共用一个数据目录轮流升级，OpenResty 把备用实例配成 `backup`，主实例排空退出时请求转到备用实例；
  - 多个进程同时服务一个数据目录时，每个进程在 5 秒内跟上其他进程做的上线与实例变化；
  - 提供 `scripts/gateway-rollout.mjs`：构建 → 起备用 → 等就绪 → 重建主 → 等就绪 → 停备用；
  - compose 增加 `gateway-standby`，两个服务的停止宽限期大于排空时间。
- **CI**：GitHub Actions 在改动网关、暴露清单或相关脚本时跑 gofmt、vet、Go 测试、`govulncheck`、控制台 lint/测试/构建、`gateway-exposure` 测试。
- **密钥轮换**：`kanyue-gateway rotate-key` 在网关停止时把库内所有密文、PocketBase 设置与最近可用快照文件从旧密钥换到新密钥；先备份、先全量校验旧密钥能解开再写入，一个事务完成；运行中的网关持有共享锁，轮换拿不到独占锁就拒绝执行。
- **目标机器验证**（外部条件）：目标规格上压测、24 小时长稳、真实 S3 恢复演练、阿里云在用能力对照。

**P1 自动化与可审计**

- **机器令牌与角色**：只读、发布者、管理员三种角色；机器令牌限定角色与可上线的环境，可单独吊销，所有操作进审计；上线生产可要求第二人批准。
- **配置即代码**：分组、域名、API、策略组、授权可导出为文件并按文件应用为草稿（不上线），可在环境之间整体比对。
- 之后按需：Prometheus 抓取与 OpenTelemetry 上报、按 OpenAPI 校验请求、响应头改写。

## Non-goals

- 不做多节点集群、共享限流存储、配置下发；
- 不在网关里做 WAF、TLS 终止、证书管理（交给 1Panel/OpenResty）；
- 不做 Lua/WASM 动态插件、开发者门户。

## Impact

- 代码：`kanyue.gateway`（同步循环、共享锁、`rotate-key`），`scripts/gateway-rollout.mjs`，`compose.yaml`，`.github/workflows/gateway.yml`
- 文档：`kanyue.gateway/README.md` 部署与升级、密钥轮换
- 数据：轮换会改写库内密文与快照文件（先备份）；旧备份仍需旧密钥解开
- 行为：多进程重叠时数据面最多落后 5 秒；升级期间不要做上线操作
