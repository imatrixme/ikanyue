## Why

老板打开小程序，最想先知道三件事：这段时间上了多少课、发了多少课时（收了多少钱）、哪些学员快没课时要续。现在这些数只能一节节、一个个学员地翻；网页后台的指标是给运维看的命令耗时，不是经营数据。

功能越多越难用。看板只回答这三件事，不做报表、图表、导出和自定义筛选。

## Product decisions (proposed)

1. **一个看板，三个时间段**：今天 / 本周 / 本月（北京时间自然日、周一开始的自然周、自然月），切换不跳页。
2. **只放四个数**：
   - 上课：确认上课的节数，以及扣掉的课时；
   - 发课时：发出的课时，以及登记的实收金额（线下登记，只做记录，不对账）；
   - 约课：新约课申请与取消的次数；
   - 新学员：这段时间加入的学员数。
3. **两张短列表**，都可以点进现有页面：
   - 「按老师」：每位老师这段时间上课的节数和扣掉的课时；只有一位老师时不显示；
   - 「需要续课」：课时快用完或快到期的学员，规则沿用续课提醒，点进去就是现有的学员台账。
4. **某个学员、某个老师的情况不新做页面**：学员看现有台账；老师看看板里他那一行，点进去是现有的老师页面。
5. **只给老板**：`isAdmin` 教师才能看；受雇老师的工作台不变。

## What Changes

- `kanyue.server`：新增 `GET /v1/workbench/dashboard?period=today|week|month`，只读，实时校验老板权限。
- `kanyue.gateway`：`mapi.json` 暴露该接口。
- `ikanyue.mini`：工作台顶部新增「经营概览」入口，进入看板页。

## Non-goals

- 不做趋势图、同比环比、自定义时间段、导出。
- 不做老师课酬统计（结算规则还没对外）。
- 不做预测和提醒推送；续课提醒仍按现有规则推送给学员。
- 不新增集合、字段或预计算表，全部按需查询。

## Capabilities

### New Capabilities
- `owner-dashboard`：老板按今天 / 本周 / 本月查看上课、发课时、约课、新学员四个数，以及按老师的上课量和需要续课的学员。

## Impact

- `kanyue.server`：`coursecredit` 新增只读查询，复用已结算课节、课时批次、预约、学员和续课规则。
- `kanyue.gateway`：暴露清单新增一条只读接口。
- `ikanyue.mini`：新增看板页和工作台入口。
- 不改数据结构，不影响学员端。
