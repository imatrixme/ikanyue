## Why

老板打开小程序，最想先知道：这段时间上了多少课、每位老师上了多少课（用来和老师对账）、哪些学员快没课时要续、哪些学员有课时却很久没来。现在这些只能一节节、一个个学员地翻；网页后台的指标是给运维看的命令耗时，不是经营数据。

功能越多越难用。看板只回答这几件事，不做报表、图表、导出和自定义筛选。

## Product decisions (confirmed 2026-10-30)

1. **一个看板，三个时间段**：今天 / 本周 / 本月（北京时间自然日、周一开始的自然周、自然月），切换不跳页；月份可往前翻看历史月份。
2. **只放四个数**：
   - 上课：确认上课的节数，以及扣掉的课时；
   - 发课时：发出的课时（**不做实收金额**：线下手填的金额不可靠）；
   - 约课：新约课申请与取消的次数；
   - 新学员：这段时间加入的学员数。
3. **按老师对账**（多位老师时）：
   - 每位老师这段时间上了几节课、扣了多少课时；
   - 点一位老师，列出他这段时间确认的每一节课（日期、时间、课程、学员），老板可以照着和老师对账；
   - **不做课酬统计**：课酬按什么规则算、发多少，由老板线下决定。
4. **两个关注名单**，都点进现有学员台账：
   - 「需要续课」：课时快用完或快到期的学员，规则沿用续课提醒；
   - 「很久没来」：手上还有课时、21 天没上课、也没有约下一节课的学员。
5. **某个学员的情况不新做页面**：看现有学员台账。
6. **只给老板**：`isAdmin` 教师才能看；受雇老师的工作台不变。

## What Changes

- `kanyue.server`：
  - `GET /v1/workbench/dashboard?period=today|week|month[&month=YYYY-MM]`：四个数、按老师、两个关注名单；
  - `GET /v1/workbench/dashboard/teachers/{teacherId}?period=`：这位老师这段时间确认的课；
  - 都是只读，实时校验老板权限。
- `kanyue.gateway`：`mapi.json` 暴露这两个接口。
- `ikanyue.mini`：工作台新增「经营概览」入口，进入看板页；老师对账页。

## Non-goals

- 不做实收金额、课酬统计、趋势图、同比环比、自定义时间段、导出。
- 不做预测和提醒推送；续课提醒仍按现有规则推送给学员。
- 不新增集合、字段或预计算表，全部按需查询。

## Capabilities

### New Capabilities
- `owner-dashboard`：老板按今天 / 本周 / 本月查看上课、发课时、约课、新学员四个数，按老师对账，以及需要续课、很久没来的学员。

## Impact

- `kanyue.server`：`coursecredit` 新增只读查询，复用已结算课节、课时分配、课时批次、预约、学员和续课规则。
- `kanyue.gateway`：暴露清单新增两条只读接口。
- `ikanyue.mini`：新增看板页、老师对账页和工作台入口。
- 不改数据结构，不影响学员端。
