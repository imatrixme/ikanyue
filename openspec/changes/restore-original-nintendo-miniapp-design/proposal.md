## Why

The later mature/institutional visual iteration diluted the clarity and precision of the first Nintendo-inspired miniapp design. Restore that original visual language as the product baseline while retaining all subsequently completed activity, points, reward, profile, refresh, and pagination behavior.

## What Changes

- Restore the first design's pure Nintendo-red, white, charcoal, and restrained semantic-color token system.
- Restore the compact hardware-interface composition for the activity, points, profile, profile-editing, points-history, reward-catalog, and activity-detail experiences.
- Remove decorative textures, oversized editorial illustrations, and asset treatments introduced by the rejected visual iterations.
- Restore compact, content-led tab and command icon treatment without copying Nintendo-owned artwork.
- Preserve current APIs, navigation, data loading, pull-to-refresh, pagination, redemption eligibility, profile editing, and logout placement.
- Add visual and structural regression evidence for the restored system at representative miniapp widths.

## Capabilities

### New Capabilities
- `original-nintendo-miniapp-visual-system`: Defines the restored first-version visual language, page composition, asset restraint, and functional-preservation requirements.

### Modified Capabilities

None.

## Impact

- Affected project: `ikanyue.taro3` only.
- Affected surfaces: shared tokens/styles/components, miniapp tab configuration, activity/points/profile-related page presentation, visual fixtures, and focused UI regression tests.
- APIs, persisted data, admin behavior, Hono behavior, and deployment topology remain unchanged.
