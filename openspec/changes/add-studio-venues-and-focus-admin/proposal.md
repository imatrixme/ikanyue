## Why

小程序首页的工作室名称、电话、地址、营业时间目前写死在 `ikanyue.taro3/src/data/studioInfo.js`，改一个字都要发版，也没法管理多个场馆。运营后台有 6 个分组、17 个页面，预约区还有多层子标签；对只想“看今天、管学员、排课、收钱”的创始人来说负担太重。

和松果一样，C 端用户将来可能关注多个场馆。切换到某个场馆后，那里可能还不能在线约课；这是场馆型产品的自然特性，也为以后 SaaS 化授权留出路径。

## What Changes

### 后台为创始人收敛（已实现）
- 侧边栏首屏只有 5 组：今天 / 学员 / 约课（日历、预约）/ 收款（订单收款、报课）/ 设置（课程、课包与价格，场馆上线后加入）。
- “更多”默认折叠，收起：
  - 教学（课堂、班级、教师工作量）
  - 账务（课时账户、异常、操作记录）
  - 积分（学员积分、实物）
  - 高级设置（预约规则、历史迁移）
- 折叠状态保存在本地。当前所在的分组即使折叠也会显示；纯老师账号不折叠。
- 预约页只保留“预约队列”和“开放配置（教师课程、开放时间）”。预约策略、冲突与迁移移到“高级设置 → 预约规则”（`/schedule/booking-settings`），旧的 `?tab=conflicts` 链接会自动跳转过去。
- 权限、路由、深链接不变，不删除任何功能。

### 场馆由后台管理（已实现）
- 新增 `venues` 集合，字段包括：名称、简介、地址、营业时间、电话、是否可在线约课、状态、排序。默认写入一条可约课的“看乐艺术”。
- 新增公开接口 `GET /v1/public/venues`，只返回启用场馆的展示字段和可约课标记。
- 后台新增“设置 → 场馆”，可以新增、编辑、停用、排序。
- 小程序：
  - 首页显示当前场馆，带“切换场馆”入口。
  - 新增独立的场馆列表页，学员在这里切换场馆，选择保存在本机。默认是第一个场馆；已停用的场馆会自动回落到第一个。
  - 当前场馆不能在线约课时，首页和约课 Tab 给出电话咨询，不显示约课选项。
- 本期不把场馆和课程、老师、课堂、课时关联。课堂的 `location` 文本保持不变；切到不可约课场馆时，首页仍显示学员课时，只把“去约课”换成电话咨询。

## Non-goals

- 不做多租户、SaaS 授权、场馆级价格或场馆级课时隔离。
- 不删除后台功能，不改权限模型。
- 不做按用户角色定制菜单。

## Impact

- Affected specs：
  - 新增 `admin-founder-focus`、`studio-venues`。
  - 修改 `admin-task-workspace`：报课入口从“账务”改为“收款”。
- Affected code：
  - `ikanyue.admin`：导航、侧边栏、预约规则页、场馆页。
  - `ikanyue.mapi.hono`：场馆集合、默认场馆初始化、公开与 ops 接口。
  - `ikanyue.taro3`：场馆页、首页、约课 Tab。
- Data：新增 `venues` 集合并写入一条默认场馆，不修改已有数据。
- Release：API 启动时会校验 ops 集合，**部署新版 API 前必须先运行 `pnpm ops:schema:apply`**（创建 `venues` 并写入默认场馆），否则 API 会拒绝启动。
