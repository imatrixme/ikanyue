## Why

课程点账本与 PocketBase 事务内核已经具备，但当前小程序仍把“课程点、批次、冻结、兑换”等内部账务概念直接暴露给学员，Admin 也仍停留在学员、积分和实物三个轻量工作区，无法完成课程配置、自动报课、班级排课、人工出勤和课后核销。现在需要把已验证的领域内核交付为符合学员与教务心智的完整产品闭环。

## What Changes

- **BREAKING**：小程序增加独立“课程”Tab，移除学员侧课程点兑换、批次、冻结和预约写操作，课程体验改为只读的课程、课时、日程和上课记录。
- 新增 Hono 学员课程投影接口，隐藏批次、课程点类型、冻结量、兑换规则、操作号和原始账本事件。
- 新增 Admin 自动报课编排：一次操作完成订单记录、课时发放、可选入班、审计和未来课堂同步任务。
- 将 Admin 改为 URL 路由化的结构化工作区，覆盖课程、课包与价格、报课订单、班级、课堂、课时账户、教师工作量、异常和审计，同时保留积分与实物模块。
- 新增无扫码条件下的人工出勤、实际教师确认、核销预览、课堂结算和结算更正流程。
- 已发布未来课堂的名单变更必须显式预览并确认，不得因报课静默修改课堂快照。
- 新增角色化导航和能力控制，教务、财务、教师和管理员仅访问其职责范围。
- 所有受影响项目要求 lines、branches、functions、statements 四项单元测试覆盖率均不低于 95%。
- 本期不实现小程序自助报课、在线支付、学员自主预约、扫码签到或现场签到联动。

## Capabilities

### New Capabilities
- `student-course-experience`: 独立课程 Tab、课程详情、课程日程、课堂详情和课时记录的只读学员体验与术语边界。
- `automatic-course-enrollment`: Admin 发起的订单、课时发放、入班、审计和未来课堂同步编排。
- `admin-course-operations`: 路由化课程运营工作区及课程、课包、报课、班级、课堂、课时账户、教师工作量和异常处理。
- `manual-lesson-settlement`: 不依赖扫码签到的人工出勤、核销预览、原子结算与更正流程。

### Modified Capabilities
- `ops-admin-system`: 从积分轻量后台扩展为角色化课程运营后台，并保留现有积分与实物能力。
- `miniapp-page-api-unit-coverage`: 将独立课程 Tab、课程只读页面、刷新分页和内部术语防泄漏纳入页面与 API 覆盖。
- `subproject-unit-test-coverage`: 对 Hono、Admin 和小程序执行四项指标均不低于 95% 的独立覆盖率门禁。

## Impact

- `ikanyue.mapi.hono`：新增学员课程投影、自动报课编排、目录管理、课堂名单修正、人工出勤和核销预览 API；复用现有 PocketBase JS SDK Batch、Outbox、幂等和审计服务。
- `ikanyue.taro3`：四 Tab 导航、新课程页面和展示组件；移除课程点原型的用户可见入口与写命令。
- `ikanyue.admin`：引入真实路由与角色化导航，新增课程运营工作区、表格、Drawer、Dialog 和自动报课流程。
- PocketBase：复用现有课程点、教学组织、课堂和审计集合；仅在缺少自动报课/同步状态字段时增加最小迁移，不承载业务 hooks。
- OpenSpec、Swagger、覆盖率配置和本地验证脚本需要同步更新；最终发布前才进行 Docker 验证。
