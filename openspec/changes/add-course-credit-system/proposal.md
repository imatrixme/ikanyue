## Why

看乐现有历史实现分别使用用户记录上的单一 `hours` 字段、课程/签到记录和轻量积分快照，无法表达不同课程不可混用的课点、购买批次、首次使用激活、有效期、兑换比例、课堂冻结与多教师结算。随着小程序、Admin、Hono API 和官网进入 `release/2.0.0` 基线，需要先建立统一且可审计的课程点领域模型，避免继续在旧课时字段或实物积分台账上叠加高风险逻辑。

## What Changes

- 建立课程商品、课程规格、通用课程点和特定课程点的统一术语与数据边界。
- 支持按原价或折扣购买课程套餐，并按订单批次发放特定课程点；课程点价值按批次保留，但每个特定课程点固定消费其对应课程的一节课。
- 支持不可直接消费的通用课程点，以及通用点到特定课程点、特定课程点之间的显式或经授权的隐式兑换。
- 为兑换规则增加方向、整数比例、有效期策略、激活策略、规则版本和防循环套利约束。
- 为课程点批次增加未激活、首次使用激活、激活截止日、有效期、延期、冻结、消费、释放、过期和冲正能力。
- 将课程商品/课包与班级拆分；支持学员多班级、课堂关联多个班级、课堂学员快照和多教师实际授课关系。
- 在课堂发生前冻结匹配的特定课程点，在出勤确认和结课后消费；取消、改期、请假、缺席和补课按版本化规则处理。
- 为教师建立与学员课程点完全独立的课堂工作量账本，并在课堂完成后按实际角色结算。
- 为 Admin 提供课程、商品、课点、兑换、班级、课堂、异常结算和审计工作区；为小程序提供余额、批次、兑换、排课资格和消费记录；官网仅承担公开课程与套餐展示。
- 为四个受影响项目建立充分的单元测试和强制覆盖率门槛，lines、branches、functions、statements 均不得低于 95%。
- **BREAKING**：后续课程权益不得继续读写 `students.hours`、`teachers.hours`，也不得复用实物积分的 `student_points` / `point_events` 作为课程点账本。

## Capabilities

### New Capabilities
- `course-credit-products`: 课程规格、套餐、价格版本、订单与批次发放规则。
- `course-credit-ledger`: 通用/特定课程点账户、不可变流水、批次、激活、有效期和人工调整。
- `course-credit-conversion`: 通用点和跨课程点兑换、规则版本、有效期策略与防套利约束。
- `teaching-organization`: 班级、班级成员、课堂、跨班合课、课堂学员快照和多教师关系。
- `lesson-credit-settlement`: 课前资格检查、批次冻结、出勤确认、课后消费、释放、冲正和补课。
- `teacher-session-credit`: 教师课堂点的独立规则、待确认收益、确认、撤销和审计。
- `course-credit-experience`: Admin、小程序和官网围绕课程点系统的角色化界面、通知和查询能力。

### Modified Capabilities
- `ops-admin-system`: Admin 从轻量积分与内容维护扩展为课程商品、课程点、班级、课堂和异常结算的结构化运营入口。
- `subproject-unit-test-coverage`: 将受影响项目的覆盖率发布门槛提高到四项指标分别 95% 以上，并纳入小程序、官网与 Hono 事务仓储代码。

## Impact

- `ikanyue.mapi.hono`: 新增课程点领域服务、基于 PocketBase JS SDK Batch API 的事务仓储、查询/命令 API、权限、幂等和对账任务；现有逐条 SDK 写入不能直接承担结算事务。
- `ikanyue.admin`: 新增课程商品、点数批次、兑换规则、班级、课堂、出勤、教师结算和异常处理工作区。
- `ikanyue.taro3`: 新增学员课程点总览、批次有效期、兑换确认、课程资格和消费记录体验。
- `ikanyue.website`: 仅展示公开课程与套餐信息，不直接读取私有余额或承担结算。
- PocketBase/持久化层：新增独立集合、索引和受控 Batch API 配置，不承载课程点业务逻辑；保留旧 `hours` 与轻量积分数据用于迁移核对，不作为新账本来源。
- 父仓库：新增跨端 PRD、技术设计、OpenSpec 规格和分阶段实施任务。
