# 看乐课程点消费系统 PRD

## 1. 文档信息

- 状态：Draft for implementation planning
- 基线：`release/2.0.0`
- 工作分支：`feature/course-credit-system`
- 覆盖系统：Admin、Hono API、小程序、官网
- 不复用对象：实物积分 `student_points` / `point_events`
- 关联技术设计：`docs/architecture/course-credit-system-technical-design.md`
- 关联 OpenSpec：`openspec/changes/add-course-credit-system/`

## 2. 背景与问题

历史系统出现过三种彼此不完整的模型：

1. 学员和教师记录上的单一 `hours` 字段，只能表示一个总量。
2. `lesson_records` 与 `attendance_records` 只表示课程和签到，未连接课程权益。
3. 当前轻量积分系统使用余额快照和事件记录，但积分用于实物兑换，不具备课程类型、批次、冻结、有效期和课堂结算语义。

这些模型无法回答以下业务问题：

- 学员有 10 节成人声乐课和 4 节视唱练耳时，各自还剩多少、何时到期。
- 同一种课程通过 3000 元原价或 2800 元优惠购买时，权益数量相同但实际价值不同，如何保留来源。
- 通用课程点为什么不能直接上课，如何按规则兑换为特定课程点。
- 1 节 A 课兑换 2 节 B 课时，如何控制比例、有效期、可逆性和循环套利。
- 学员加入班级后何时检查课程点、何时冻结、请假或改期后如何释放。
- 一堂课关联多个班级、多个学员和多个老师时，如何避免重复扣点并正确结算教师工作量。

## 3. 产品目标

- 建立从购买、发放、激活、兑换、冻结、消费、过期到冲正的完整课程点生命周期。
- 让每个课程点批次都能追溯到订单、价格、规则版本和操作人。
- 让班级关系与课程权益解耦；加入班级不扣点，实际课堂结算才消费点数。
- 让通用课程点只承担兑换媒介，不承担课堂消费。
- 让学员消费点和教师课堂点使用完全独立的账户与规则。
- 在并发报名、重复提交、系统重试和部分失败下保持账实一致。
- 为 Admin 提供异常处理能力，为学员提供可理解的余额、到期和兑换信息。
- 确保所有受影响项目拥有充分的单元测试，行、分支、函数和语句覆盖率分别达到 95% 以上。

## 4. 非目标

- 第一阶段不提供学员之间转赠或交易课程点。
- 第一阶段不提供公开的自由兑换市场，所有比例由管理员发布的规则决定。
- 第一阶段不提供自动现金退款，但数据模型必须支持订单撤销和权益冲正。
- 不将实物积分与课程点合并，不允许用实物积分购买课程。
- 不允许客户端直接修改余额、有效期、课堂消费结果或教师收益。
- 官网第一阶段不直接展示私有余额，也不承担课堂结算。

## 5. 角色

- 学员：购买或获得权益、兑换、查看余额、报名/参加课程、查看消费记录。
- 监护人：经授权管理未成年学员的购买、兑换和课程安排。
- 教师：查看授权班级和课堂、确认出勤、提交结课、查看自己的课堂点。
- 教务：管理班级、排课、名单、请假、补课和结算异常。
- 财务/运营：管理课程商品、价格、订单、发放、兑换规则和批次调整。
- 管理员：管理规则和权限，处理冲正、延期、冻结和审计。
- 系统任务：执行过期、通知、对账和失败操作恢复。

## 6. 统一术语

- 课程规格：可被一节课堂消费的精确教学 SKU，例如“成人声乐一对一 60 分钟”。
- 通用课程点：不可直接参加课堂，只能兑换为特定课程点的额度。
- 特定课程点：绑定一个课程规格，1 点仅能消费该规格的一节课堂。
- 套餐：一次购买后发放一条或多条特定课程点批次的商品。
- 价格版本：某个商品在一段时间内的标价、实付规则和发放内容。
- 批次：一次购买、兑换、赠送、补偿或迁移形成的一组同源点数。
- 班级：持续的教学组织关系，不是商品，也不是权益账户。
- 课堂：在具体时间真实发生的一次教学事件。
- 冻结：为某节未来课堂占用指定批次点数，但尚未消费。
- 结算：根据课堂状态与出勤规则，将冻结点消费或释放，并生成教师课堂点。
- 教师课堂点：教师工作量单位，不等于任何学员课程点。

## 7. 核心不变量

- PRD-R001：通用课程点永远不能直接消费课堂。
- PRD-R002：课堂只能消费其快照中指定的特定课程点类型。
- PRD-R003：每个特定课程点的最小消费单位为整数，当前每节课固定消费 1 点。
- PRD-R004：加入、退出或切换班级不得直接修改课程点余额。
- PRD-R005：所有点数变化必须生成不可变流水，并指向一个业务操作。
- PRD-R006：同一课堂与同一学员最多成功消费一次。
- PRD-R007：同一课堂、教师和角色最多成功结算一次教师课堂点。
- PRD-R008：规则变更不得重算已经购买、兑换、冻结或结算的历史记录。
- PRD-R009：客户端提交的余额、价格、兑换结果和结算结果不具有权威性。
- PRD-R010：冻结、消费、兑换和冲正必须使用幂等键。
- PRD-R021：任一受影响项目的行、分支、函数或语句覆盖率低于 95% 时不得进入发布验证。

## 8. 课程规格、商品与价格

### 8.1 课程规格

课程规格至少由课程主题、授课形式、标准时长和可选教师等级组成。只要这些维度影响可用范围或价格，就必须拆成不同课程点类型。

同一个课程规格涨价时，默认不创建新课程点类型；已有点数仍保持 1 点兑换 1 节。只有权益内容发生变化，例如 45 分钟改为 60 分钟，才创建新类型。

### 8.2 套餐

一个套餐可以发放多个课程点批次，例如：

```text
声乐成长套餐
- 成人声乐一对一 8 点
- 视唱练耳小组课 2 点
```

套餐不是班级。购买套餐不会自动把学员加入某个班级，除非订单完成后执行独立的报名流程。

### 8.3 价格与价值

价格版本必须保存原价、实付价、币种、有效期和发放内容。购买 10 节标价 300 元的课程：

```text
标价总额：3000 元
实付总额：2800 元
发放数量：10 点
标价单点价值：300 元
实际单点成本：280 元
```

同类型点数可以因活动、渠道或订单不同而具有不同成本基础，但课堂消费都按 1 点处理。

### 8.4 通用课程点商品

通用课程点必须使用稳定计量单位。推荐使用“兑换额度”语义，例如 1 通用点代表 1 元标称兑换额度，但支付价格可以优惠：

```text
支付 2800 元 -> 发放 3000 通用点
300 通用点 -> 1 个 A 课程点
150 通用点 -> 1 个 B 课程点
```

充值优惠和课程兑换比例必须是两套独立、可版本化的规则。

## 9. 订单与发放

### 9.1 订单类型

- 通用点充值订单：支付成功后发放通用课程点批次。
- 套餐购买订单：支付成功后直接发放特定课程点批次，不经过用户可见的通用点账户。
- 管理员线下订单：记录现金、转账或其他线下渠道后发放权益。
- 赠送/补偿单：不产生支付，但必须记录原因、审批人与成本归属。

### 9.2 订单规则

- PRD-R011：订单必须快照商品、价格版本、发放内容、有效期和激活策略。
- PRD-R012：同一支付成功通知只能发放一次。
- PRD-R013：支付失败或取消不得发放课程点。
- PRD-R014：订单冲正必须通过反向流水处理，不能删除已发放批次。
- PRD-R015：已消费权益发生订单撤销时必须进入人工异常处理，不得产生负余额。

## 10. 账户、批次与余额

每个学员按课程点类型拥有账户视图，但实际余额由多个批次组成。批次至少区分：原始数量、可用、冻结、已消费、已过期和已冲正数量。

批次状态：

```text
pending -> unactivated -> active -> depleted
                         -> expired
pending/unactivated/active -> cancelled
```

用户总览必须同时展示：

- 可用点数。
- 已冻结点数。
- 未激活点数。
- 最近到期数量和日期。
- 当前无法直接消费的通用点。

批次明细必须展示来源、获得日期、激活规则、有效期、剩余数量和限制。

## 11. 首次使用激活与有效期

### 11.1 激活模式

- `GRANT_TIME`：发放时立即激活。
- `FIRST_RESERVATION`：第一次成功预约时激活。
- `FIRST_CHECK_IN`：第一次有效签到时激活，滚动课包默认使用此模式。
- `FIRST_COMPLETED_SESSION`：第一次课程完成时激活。
- `TERM_START`：固定班课按本期开课时间激活。

规则不得只写“首次使用”，必须明确触发事件。

### 11.2 未激活批次

- 必须有激活截止日，防止永久不失效。
- 允许为激活截止日前发生的课堂预冻结。
- `FIRST_CHECK_IN` 模式下，预约和取消不应直接激活。
- 第一节候选课堂取消时，应释放冻结并等待下一次有效触发。
- 激活时写入 `activated_at` 和实际 `expires_at`，且只能执行一次。
- 激活后如果已有未来预约落在有效期外，必须重新分配其他批次或标记资格不足。

### 11.3 有效期判断

有效区间采用：

```text
valid_from <= session.start_at < expires_at
```

以课堂开始时间判断是否有效，不以后台最终结算时间判断。

### 11.4 过期与延期

- 未冻结的到期余额转为过期，不得删除。
- 为到期前课堂冻结的点，即使稍后结算，仍可正常消费。
- 取消课堂时若原点数已过期，释放后立即过期，不重新变为可用。
- 延期必须记录原日期、新日期、理由、操作人和审批人。
- 延期默认只影响尚未消费的剩余数量；恢复已过期点数必须生成新的补偿批次。

## 12. 兑换

### 12.1 支持范围

- 通用课程点兑换特定课程点。
- 特定课程点兑换另一种特定课程点，例如 1 A -> 2 B。
- 不支持冻结、已消费、已过期或被锁定批次参与兑换。
- 不支持小数点数；兑换数量必须是规则最小步长的整数倍。

### 12.2 显式与隐式兑换

显式兑换由用户进入兑换页面主动完成。隐式兑换可以发生在报名或排课资格检查中，但必须先展示来源、目标数量、比例、有效期和不可逆提示，并获得用户本次确认或有效的自动兑换授权。

隐式兑换仍必须先创建完整兑换操作，再冻结新生成的特定课程点，不能直接用通用点抵扣课堂。

### 12.3 兑换规则

兑换规则必须是有方向、有版本的配置，至少包含：来源类型、目标类型、整数比例、最小步长、生效时间、失效时间、有效期策略、激活策略和可逆性。

有效期策略：

- `INHERIT_SOURCE`：继承来源批次有效期。
- `RESET_ON_CONVERSION`：兑换时重新计算。
- `RESET_ON_ACTIVATION`：目标批次首次激活时重新计算。
- `MIN_SOURCE_AND_NEW`：来源有效期和新规则有效期取较早值。
- `TARGET_TERM_END`：使用目标固定班期结束时间。

多来源批次兑换时，目标批次必须保留来源分配关系；不同有效期结果不得无条件合并。

### 12.4 防套利

- PRD-R016：兑换规则默认不可逆，不自动生成反向规则。
- PRD-R017：存在反向路径时，系统必须校验参考总价值不增长。
- PRD-R018：规则不得形成可无限增加任一课程点余额的兑换环。
- PRD-R019：规则发布前必须通过兑换图检测和样例模拟。
- PRD-R020：规则版本下线不影响历史兑换，但阻止新的兑换请求。

## 13. 班级、报名与课堂

### 13.1 班级

班级保存名称、课程规格、班期、容量、默认地点、默认教师和状态。学员与班级、教师与班级均为多对多关系，并带生效时间和角色。

加入班级只建立教学组织关系，不扣点、不兑换点，也不保证未来每节课都有资格。

### 13.2 课堂

课堂是结算最小单位，必须快照：课程点类型、消费数量、开始/结束时间、地点、结算规则版本和默认教师。

一堂课可以关联多个班级，用于合班授课。课堂学员必须形成独立快照，不能在结算时动态读取当前班级名单。

同一学员同时属于多个关联班级时，只能生成一个课堂学员记录，避免重复扣点。

### 13.3 课堂教师

班级教师是默认安排，课堂教师是实际安排。代课、助教和临时增加教师必须写入课堂教师关系，并在结课时确认实际状态。

## 14. 资格检查、冻结和结算

### 14.1 资格检查

系统在排课后和开课前截止时间执行资格检查：

1. 查找完全匹配的特定课程点。
2. 按最早到期优先分配批次。
3. 若不足且存在通用点/兑换规则，向用户提供兑换方案。
4. 用户确认后原子完成兑换和冻结。
5. 仍不足则标记 `credit_insufficient`，提前通知学员与教务。

不得等到正式开课时才首次发现点数不足。

### 14.2 冻结

- 冻结必须绑定具体批次和课堂学员记录。
- 一个批次可以为多节课冻结，但可用量不能低于零。
- 冻结顺序默认最早过期优先；同日期下按业务优先级和发放时间排序。
- 同一课堂学员的重复冻结请求必须返回原结果。

### 14.3 出勤状态

课堂学员状态至少包括：`scheduled`、`credit_insufficient`、`reserved`、`checked_in`、`present`、`late`、`leave`、`absent`、`cancelled`、`settled`。

出勤状态和点数结算状态必须分开，避免“已签到但尚未扣点”被错误理解为完成。

### 14.4 结算规则

- 到课、迟到：默认消费冻结点。
- 学员在允许时间前请假：默认释放冻结点。
- 超时取消或无故缺席：按课堂快照中的缺席规则消费或释放。
- 机构取消：释放冻结点，不产生教师课堂点。
- 课堂改期且新时间超出批次有效期：释放并重新分配有效批次。
- 补课：创建新的课堂记录，不修改原课堂事实；原课堂按请假/缺席规则完成结算。
- 管理员例外：必须填写原因并进入审计，不允许静默负余额。

### 14.5 课堂状态

```text
draft -> scheduled -> enrollment_closed -> in_progress -> completed -> settled
                        -> cancelled
completed/settled -> correction_pending -> settled
```

只有 `completed` 课堂可以进入正常结算。`settled` 后修改名单、课程点类型或教师必须走冲正流程。

## 15. 教师课堂点

教师课堂点是独立工作量账本，不与学员消费点守恒。规则可以依据课程规格、时长、主讲/助教角色、实际授课和人数计算。

教师课堂点状态：`pending`、`confirmed`、`reversed`。

- 课堂完成后按实际课堂教师生成 `pending` 收益。
- 教务确认后变为 `confirmed`。
- 代课老师获得收益，未实际授课的默认老师不得获得收益。
- 多教师分别按角色规则结算。
- 机构取消的课堂默认不产生收益；特殊补偿通过独立调整规则处理。
- 教师收益冲正必须指向原课堂和原收益事件。

## 16. 小程序体验

- “我的课程点”按课程类型展示可用、冻结、未激活和即将到期数量。
- 通用课程点单独显示“仅可兑换”，不能出现“可上课”文案。
- 批次详情展示来源、剩余、激活截止日、有效期和限制。
- 兑换确认页展示来源点、目标点、比例、规则版本摘要、有效期变化和不可逆性。
- 课程/课堂页面展示是否具备资格、已冻结批次、需要兑换或点数不足。
- 消费记录按课堂展示，而不是只展示匿名数量变化。
- 支持下拉刷新、分页历史和明确的网络/空/失效状态。

## 17. Admin 体验

Admin 采用结构化工作区，不使用一页内无限 View 切换：

- 课程与商品：课程规格、套餐、价格版本、发布状态。
- 课程点账户：学员总览、批次、流水、冻结和即将到期。
- 兑换规则：有向比例、有效期策略、模拟、发布和停用。
- 班级：成员、默认教师、课程规格和班期。
- 课堂：多班关联、名单快照、实际教师、资格和出勤。
- 结算中心：待结算、失败、余额不足、重复、改期和冲正。
- 教师课堂点：待确认收益、规则和历史。
- 审计：按订单、学员、批次、课堂、操作人和幂等键追踪。

高风险操作使用复核弹窗，必须展示影响数量、批次、有效期和关联课堂。

## 18. 官网边界

官网可以展示公开课程规格、套餐原价/活动价、适用人群和有效期说明。官网不得直接读取学员私有课程点、班级名单和教师结算数据。

官网购买入口可以跳转小程序或受控支付流程，但最终订单确认和权益发放仍由后端完成。

## 19. 权限与审计

- 学员只能查看自己的订单、批次、兑换、课堂与消费记录。
- 监护人只能访问明确绑定的学员。
- 教师只能查看被授权班级/课堂的必要学员信息和自己的收益。
- 教务可排课、处理出勤和发起结算，但不能修改价格规则。
- 财务/管理员可管理商品、订单和点数调整。
- 兑换规则发布、批次延期、冲正和负面调整必须拥有高权限并记录审批上下文。
- 审计记录必须包含操作者、角色、动作、对象、前后摘要、原因、时间和请求追踪 ID。

## 20. 通知

系统至少支持以下通知事件：

- 订单支付成功与权益发放。
- 未激活批次接近激活截止日。
- 批次即将到期。
- 课堂资格不足或需要兑换。
- 兑换成功及有效期变化。
- 课堂取消、改期、请假结果和补课安排。
- 课堂消费完成。
- 教师课堂点待确认、确认或撤销。

通知失败不得回滚账本操作，但必须可重试并保留状态。

## 21. 报表与对账

- 学员课程点余额、批次和即将到期报表。
- 通用点到课程点的兑换流向与规则版本报表。
- 套餐销售额、标价、实付和未履约课程点数量。
- 课堂应到、实到、请假、缺席、点数消费与异常报表。
- 教师课堂点待确认和已确认报表。
- 账本事件与批次快照差异报表。

系统必须可以从不可变流水重建批次数量，并定期校验快照。

## 22. 异常处理矩阵

| 场景 | 系统处理 |
| --- | --- |
| 支付通知重复 | 返回原发放结果，不重复生成批次 |
| 同时报名两节课 | 事务内锁定/校验批次，第二次不足则失败 |
| 兑换成功但冻结失败 | 整个事务回滚；不得留下孤立目标批次 |
| 课堂取消时批次未过期 | 释放回原批次可用量 |
| 课堂取消时批次已过期 | 释放后立即转入过期量 |
| 课堂结算发生在点数到期后 | 只要课堂发生时间有效且已冻结，允许消费 |
| 学员重复出现在多个合班名单 | 去重后只生成一个课堂学员和一次冻结 |
| 教师临时代课 | 以实际课堂教师结算，保留变更审计 |
| 已结算课堂修改出勤 | 先冲正原结算，再按新事实重新结算 |
| 规则下线 | 历史记录保留，新请求拒绝 |
| 兑换形成增值环 | 发布前阻止规则生效 |
| 延期已过期点数 | 通过补偿批次恢复，不覆盖历史过期事实 |

## 23. 验收标准

- 能同时持有通用点和至少三种互不通用的特定课程点。
- 能购买 3000 元原价或 2800 元优惠的同一 10 节套餐，并保留不同成本批次。
- 能完成 300 通用点 -> 1 A、1 A -> 2 B 的兑换，且课堂不能直接消费通用点或 A 点代替 B 点。
- 能为滚动课包在首次有效签到时激活，并计算有效期；固定班课能按班期开课日激活。
- 能在课前冻结、课后消费、请假释放、过期释放和改期重新分配。
- 同一学员跨多个合班关系只扣 1 点。
- 多名教师按实际角色分别生成课堂点，且不与学员消费数量强制相等。
- 重复支付、重复冻结、重复结算和重复冲正不会改变第二次结果。
- 任意余额变化都能追踪到订单、兑换、课堂或人工操作。
- Admin、小程序与官网只展示各自权限范围内的数据。
- Admin、Hono、小程序和官网中所有受影响项目均提供可重复的本地覆盖率命令，四项覆盖率分别不低于 95%。
- 课程点批次、激活、有效期、兑换、冻结、结算、冲正和教师课堂点的关键分支均有成功与失败路径测试。

## 24. 分阶段范围

### Phase 0：领域与事务基础

数据模型、迁移、事务命令、幂等、不可变流水、批次重建和对账。

本阶段同时建立四端覆盖率阈值；后续任何阶段都不得通过降低阈值换取发布。

### Phase 1：商品、直接套餐与课堂结算

课程规格、套餐、订单发放、班级、课堂、冻结、出勤和教师课堂点。不开放跨课程兑换。

### Phase 2：通用课程点与兑换

通用点充值、显式兑换、隐式兑换确认、有效期策略和防套利检查。

### Phase 3：自动化与运营

到期任务、通知、异常中心、批量排课、自动兑换授权和经营报表。

## 25. 发布前必须确认的产品决策

- 通用课程点是否等价于 1 元标称兑换额度。
- 滚动课包默认使用首次签到还是首次完成课程激活。
- 各课程类型的激活截止日和有效期。
- 请假截止时间、无故缺席和迟到的扣点规则。
- 课程取消与教师补偿规则。
- 是否允许特定课程点反向兑换，以及允许的最大价值损耗范围。
- 监护人与学员账户的绑定和支付归属。
- 第一阶段支持的支付渠道和线下订单审批流程。
