## Context

当前首个 tab 仍复用 `pages/activity/index` 作为活动列表页，页面主体是左侧日期分组加右侧活动列表的双栏布局。现有“今天”到“已结束”全部通过统一的日期范围筛选右侧活动数据，但本次需求要求保留近期活动列表的同时，把末尾两个入口改成承载静态介绍信息的首页导航项。

代码层面已经存在基于页面参数解码的跳转模式，例如 `pages/webview` 会通过 `decodeURIComponent` 读取 URL 参数，因此新增图片详情页可以延续相同参数约定而不引入新的状态管理方式。

## Goals / Non-Goals

**Goals:**
- 保持 `pages/activity/index` 作为首个 tab 页面路径不变，仅将其对外文案调整为“首页”。
- 保留“今天”到一周内日期分组的活动筛选行为。
- 让“学什么”和“关于看乐”作为静态信息入口，点击后跳转到图片详情页。
- 新增一个接收图片 URL 参数的图片详情页，用于展示远程图片占位内容。

**Non-Goals:**
- 不重构活动接口、活动详情页或现有活动筛选算法。
- 不引入后台配置或 CMS 来动态维护图片入口内容。
- 不修改“我的”等其他 tab 的结构或导航逻辑。

## Decisions

### 1. 继续复用 `pages/activity` 作为首页承载页

将 tabBar 文案与 `activity` 页面导航栏标题改为“首页”，但保留页面路径与现有组件文件位置不变。

选择原因：
- tabBar 已绑定 `pages/activity/index`，保留路径可以避免额外的路由迁移和页面注册调整。
- 现有页面已经具备首页所需的近期活动列表展示能力，本次只需补充静态入口行为。

备选方案：
- 新建 `pages/home/index` 并替换 tabBar 路径。放弃原因是改动面更大，且对当前需求没有额外价值。

### 2. 将“学什么”“关于看乐”建模为带导航动作的左侧分组项

在 `dateGroups` 中继续维护统一的数据结构，但为静态入口项增加导航元数据，例如 `action: 'navigate-image'`、`imageUrl` 和目标标题。点击分组时优先判断是否为导航项；若是，则直接跳转，不更新右侧列表筛选状态。

选择原因：
- 可以在保持当前列表渲染结构的前提下，最小化模板层改动。
- 避免通过“判断最后两个索引”这类脆弱逻辑耦合页面顺序。

备选方案：
- 在模板里单独拆出两种左侧单元。放弃原因是会增加分支渲染和样式维护成本。

### 3. 新增独立图片详情页，而不是复用 `webview`

新增 `pages/imageDetail/index`，通过页面参数读取图片 URL，并使用原生 `<image>` 组件展示远程图片。

选择原因：
- 图片详情页只需要展示单张图片，不需要网页容器与外部站点能力。
- 直接使用图片组件更容易控制加载失败提示、缩放模式和页面标题。

备选方案：
- 复用 `pages/webview/index` 打开图片链接。放弃原因是用户会进入浏览器式容器，体验不符合“图片详情页”的预期。

### 4. 使用 URL 编码传递远程图片地址

首页跳转时使用 `encodeURIComponent(imageUrl)` 传参，图片详情页在 `onLoad` 中用 `decodeURIComponent` 解码；缺少参数时给出提示并返回上一页。

选择原因：
- 与仓库内已有的页面参数处理模式一致。
- 可以避免远程 URL 中的特殊字符破坏路由查询串。

## Risks / Trade-offs

- [远程图片加载失败] → 图片详情页需要提供加载失败提示，避免白屏无反馈。
- [静态入口不切换右侧内容可能让选中态产生歧义] → 点击“学什么”“关于看乐”时保持原有活动分组选中态，不把静态入口误标为当前活动筛选条件。
- [继续复用 `activity` 页面命名可能造成代码语义滞后] → 在文档和规格中明确其首页职责，后续若继续扩展首页再评估是否重命名目录。

## Migration Plan

1. 注册图片详情页到页面配置中。
2. 更新 tabBar 文案与 `activity` 页标题文案为“首页”。
3. 调整首页左侧分组定义与点击逻辑，新增两个静态入口。
4. 发布后在微信开发者工具和 H5 端验证首页入口、跳转和图片展示。
5. 若需回滚，只需移除图片详情页注册并恢复原有两个分组文案与点击行为。

## Open Questions
